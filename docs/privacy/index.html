In one paragraph

NetXRay is a developer tool that inspects the network traffic of a page you are already looking at in Chrome DevTools. Everything it reads — requests, headers, response bodies, cookies, page storage and TLS details — is processed on your own computer and is never transmitted anywhere. The extension has no servers, no account, no telemetry, no analytics and no advertising, and it does not sell or share data. Captured sessions are kept only in Chrome’s chrome.storage.session, which lives for the browser session and is cleared when you clear the session, navigate, or close the browser.

1. What NetXRay accesses

NetXRay only sees traffic for the tab whose DevTools panel you opened, and only while that panel is open. It reads the following categories of data:

Request and response metadata

Through Chrome’s own DevTools APIs (chrome.devtools.network), NetXRay reads the URL, method, status code, headers, timings, sizes, resource type, server IP address and HTTP protocol of each request the inspected page makes. This is the same information the DevTools Network panel shows you.

Request and response bodies (optional)

Textual bodies (HTML, JSON, XML, JavaScript, GraphQL) are read so that rules can look for leaked secrets, verbose stack traces and similar problems. Body capture is on by default and can be switched off at any time in NetXRay’s Settings. Bodies are capped at 256 KB, are held in the panel’s memory only, and are never written to session storage — a recovered session always comes back without bodies.

Cookies

For the inspected page’s address, NetXRay reads cookie names, values, domain, path, Secure/HttpOnly/SameSite flags and expiry dates so it can warn about unsafe cookie configuration. Reading is read-only: NetXRay never sets, edits, deletes or sends cookies.

Page web storage (only on request)

localStorage and sessionStorage keys and values for the inspected origin are read only when you press Read page storage in the Storage view. Keys and values are truncated at 500 characters and are not persisted.

TLS and certificate details (only if you opt in)

Certificate subject/issuer, validity dates, SANs, TLS version and cipher are read only after you explicitly enable Deep TLS inspection, which asks Chrome for the optional debugger permission. While it is attached Chrome shows its standard “started debugging” infobar, and you can turn it off at any time. NetXRay cannot attach to chrome:// pages or the Chrome Web Store, and it detaches when you disable the feature.

Your NetXRay preferences

Interface settings (theme, “Teach me” mode, body capture, whether you have seen the tour) are stored in the extension page’s own localStorage on your device. They contain no browsing data.

2. Where data is stored and how long it is kept

Data Where How long
Captured request metadata (up to the last 1,200 requests per tab) chrome.storage.session, in memory, on your device Until you clear the session, the tab navigates, or the browser closes. Never written to disk by NetXRay.
Request/response bodies Panel memory only Recovered sessions never include bodies.
Cookies and web-storage values Panel memory only Discarded when the panel closes or the session is cleared.
TLS details chrome.storage.session, in memory Until Deep TLS inspection is turned off, the session is cleared, or the browser closes.
Preferences Extension localStorage, on your device Until you change them or uninstall the extension.

Because NetXRay keeps captured data in chrome.storage.session, nothing is retained across browser restarts. You can erase the current session at any time with the Clear session (×) button. Uninstalling the extension removes its stored preferences; Chrome discards session storage automatically.

3. What NetXRay never does

  • No transmission. The extension makes no outbound network requests of its own. It has no backend, no API keys and no remote configuration. Captured data never leaves your computer except when you export a file yourself.
  • No accounts. NetXRay has no sign-in, so it holds no name, email address, password or payment information.
  • No tracking. No analytics, crash reporting, telemetry, fingerprinting, advertising or profiling. No data is used to determine creditworthiness or for lending purposes.
  • No selling or sharing. Data is not sold, rented, transferred or disclosed to the developer, to advertisers, or to any third party.
  • No remote code. All code ships inside the extension package and runs under a strict content security policy (script-src 'self'; object-src 'none'; base-uri 'none'). Nothing is fetched or evaluated at runtime, and page content is never executed.
  • No reading in the background. NetXRay only observes the tab whose DevTools panel you deliberately opened, and only while that panel is open. It has no access to your browsing history, other tabs, bookmarks or downloads.
  • No human review. Nobody — including the developer — can read your captured data, because it is never sent to anyone.

4. Files you create

Exports are generated in the panel and saved by your browser to your download folder:

  • HAR — the standard DevTools format. It contains raw headers and bodies, so treat it as sensitive.
  • JSON and HTML reports — normalized events, findings and score, with recognized secrets masked. The HTML report is fully self-contained and loads nothing from the network.

Exported files are ordinary files on your computer, under your control. NetXRay cannot see, upload or delete them after export; storing or sharing them is your decision.

5. Why each permission is requested

Permission Purpose
cookies + host access Read cookie attributes for the inspected page so unsafe cookie flags can be flagged. Read-only.
storage Keep the crash-recovery session snapshot in chrome.storage.session.
scripting Run one small, fixed function to list page storage, and only when you click the button.
debugger (optional) Obtain TLS and certificate details for deep TLS findings, only after you enable it.
DevTools panel APIs Read requests and timings for the inspected tab, equivalent to the Network panel.

6. Scope and responsibilities

NetXRay is intended for developers testing applications they own or are explicitly authorized to test. It does not filter what it captures: a session can contain personal data, session tokens and live credentials belonging to whoever used the inspected site. You are responsible for handling captured and exported data in line with the law and your organization’s policies. Use NetXRay only where you have permission to inspect traffic.

7. Children

NetXRay is a developer tool for professional use and is not directed to children under 13. It collects no personal information from anyone, including children.

8. Changes to this policy

If NetXRay’s data handling changes, this page will be updated and the “last updated” date above will change before the new version is published. Material changes will also be noted in the extension’s release notes and in the Chrome Web Store listing. Continuing to use a new version after the policy changes means you accept the updated policy.
